# 班级消息日历

把 QQ 班级群里的通知，自动整理成日历上的日程。

零依赖 · 无需构建 · 离线可用 · 数据只存在你自己的浏览器里

---

## 解决什么问题

班级群里班委发通知，消息一多就被聊天记录淹没；"下周三下午三点开会"这种信息，看的时候记住了，过两天就忘。

这个工具做的事很简单：**把群消息粘贴进来，自动整理成结构化的日程，落到日历上。**

```
输入：
  【班会通知】本周五下午3点在教学楼B203开班会，请准时参加
  @全体成员 10月20日前把社会实践报告的电子版发给我，迟交扣分

输出：
  10月17日 周五 15:00   班会          教学楼B203
  10月20日 周二 全天    提交社会实践报告
```

## 功能

| 功能 | 说明 |
|---|---|
| 自动抽取 | 从自由文本中识别日期、时间、事项、地点 |
| 相对日期换算 | "下周三""本周五"自动换算为具体日期（提示词会附带当前时间作为基准） |
| 中文月视图 | FullCalendar 驱动，支持月 / 列表视图切换，点击日期可手动添加 |
| 导入前核对 | 解析结果以可编辑列表呈现，可逐条修改或取消勾选 |
| 一键导出 .ics | 生成标准日历文件，导入 iOS / Android 系统日历 |
| 数据本地化 | 日程与 API Key 只存在浏览器 localStorage，不经过任何第三方服务器 |
| 零依赖 | 不需要 npm、不需要构建、不需要安装任何东西，前端库已内置 |

## 快速开始

### 1. 获取项目

```bash
git clone <本项目地址>
cd qq-calendar
```

或在项目网页上点 `Code` → `Download ZIP` 解压。

### 2. 打开

双击 `index.html`，浏览器会自动打开页面。不需要安装任何东西，也不需要启动服务。

### 3. 配置解析能力（只需一次）

**方式 A · 配置 API Key（推荐，可一键解析）**

点右上角「设置」，填入 DeepSeek API Key（在 [platform.deepseek.com](https://platform.deepseek.com) 创建）。Key 只保存在本地浏览器。

**方式 B · 不配置 Key（手动模式）**

点「复制解析提示词」→ 把提示词和群消息一起发给任意对话式 AI → 把 AI 返回的 JSON 粘回页面 → 导入。效果相同，只是多两步手工操作。

### 4. 使用

点「导入群消息」→ 粘贴班群里的通知（可一次贴多条）→ 「智能解析」→ 核对修改 → 「加入日历」。

需要同步到手机时，点「导出 .ics」，把文件传到手机后用系统日历打开即可。

## 工作原理

整条链路只有**解析**这一步需要联网，其余全部在浏览器本地完成：

1. **提示词构造** —— 把当前时间、抽取规则、输出格式拼成一段指令，连同群消息一起发给模型
2. **模型解析** —— 返回固定结构的 JSON（`date` / `time` / `title` / `place` / `raw`）
3. **规整入库** —— 过滤掉日期非法或标题为空的记录，其余写入 localStorage
4. **渲染与导出** —— FullCalendar 渲染月视图，并可按需导出 .ics

之所以没有后端，是因为 DeepSeek 接口允许浏览器跨域直连。这换来了零部署与零依赖；代价是 API Key 会存在浏览器里，**请不要在公共电脑上配置 Key**。

## 项目结构

```
qq-calendar/
├── index.html      主程序（界面、样式、逻辑全在这一个文件里）
└── vendor/         第三方库，已内置以支持离线使用
```

把界面、样式、逻辑都放在单个 `index.html` 里是刻意的选择：不用构建、不用打包，整个文件夹复制到哪都能直接跑。

## 开发

改动前端后刷新页面即可，没有构建步骤。代码全在 `index.html` 里：

- 样式在顶部 `<style>` 中，配色集中在 `:root` 变量，改一处即可换肤
- 逻辑在底部 `<script>` 中，纯函数（`buildPrompt`、`extractJson`、`normalizeEvents`、`toICS`）与应用初始化是分开的

## 常见问题

**一定要 API Key 吗？**
不一定。不配置 Key 时可用手动模式，借助任意对话式 AI 完成解析，只是多两步复制粘贴。

**数据会上传吗？**
日程和 Key 只存在你的浏览器本地。只有群消息文本会发送给你配置的模型接口，用于解析。

**支持微信、钉钉群吗？**
支持。输入是纯文本，任何来源的消息都能解析。

**能全自动吗？不想手动粘贴。**
本项目定位是零依赖的轻量工具，刻意不做协议接入。如果确实需要自动接收 QQ 群消息，可以另行接入 [NapCat](https://github.com/NapNeko/NapCatQQ) 等 OneBot 实现作为消息源，复用同一套解析逻辑。

**解析准吗？**
取决于模型。相对日期换算、多事项拆分这类任务，主流模型表现已经不错。界面在导入前提供了逐条编辑与勾选，建议核对后再入库。

## 已知限制

- **图片类通知无法识别**。班委常发通知截图，目前只能处理文本，需要多模态模型或 OCR 才能覆盖。
- **无多群区分**。日程未记录来源群，暂不支持按群筛选。
- **仅本地存储**。换浏览器或清除站点数据会丢失日程，重要数据请用「导出 .ics」备份。
